URLs inventoried were read from sitemaps only. URLs classified were fetched live and their AEM template marker recorded. Pages deeply analyzed had their full HTML, components, integrations, media, forms and SEO tags extracted. Regional comparisons fetched the same path on each regional domain and compared it with the primary.

1 · Sitemap analysis and URL clustering

Each domain's robots.txt lists one marketing sitemap (www also lists the Korean sitemap under /ko-kr/). All six were parsed in full. Each entry carries 25–30 hreflang alternates linking the regional equivalents, which gave a direct path-level mapping between sites. URLs were clustered by first and second path segment (68 clusters on www) and every URL was then assigned to a proposed EDS template by path rule.

2 · Primary-site selection and stratified sampling

Deep sample: 59 www pages chosen per cluster (1–3 per cluster, more for large clusters such as video hub, news center, products, events), plus deliberate picks of integration-heavy pages (faceted product listing, PDP with buy box, search, kit selector, forms). Each page: template marker, AEM component ids (text-…, container-…), BEM component roots, parbase components, iframes, forms, PDFs, tables, video, third-party hosts, SEO tags, page weight.

3 · Template discovery (source AEM templates)

Modern pages expose <meta name="template"> (homepage-template, basicpage-template, pdp-template, systems-page-template). Legacy pages expose <meta name="pageTemplate"> (e.g. /apps/illumina-marketing/templates/bootstraplandingpage). A random census of 450 URLs recorded these markers: 14 source templates, 90% legacy. Source templates were then consolidated into 15 EDS templates by page purpose (e.g. four article-like legacy templates → one Article template with variants).

4 · Component and block discovery

Components were identified from AEM component ids, BEM roots (hero__, instrumentspecs__, product-summary__…), legacy parbase names (productLongDescription) and the rendered DOM. Each was mapped to an EDS block; duplicates across generations (legacy tiles vs modern cards) were merged.

5 · Integration discovery

Three sources: (1) third-party hosts in page HTML, (2) live browser network capture on interactive pages (search, listing, kit selector, video hub, PDP), (3) the supplied Third-Party Integrations Inventory (AEM 6.5 LTS upgrade) and AEM architecture diagram. Network capture added items not in the inventory (MaxMind/geoip-js, Qualtrics, ZoomInfo, Reddit, AEP Web SDK, chinalytics, Baidu).

6 · Regional equivalence test

For every source template, 1–2 www URLs with the widest regional coverage were fetched on each regional site. Compared: template marker, set of CSS classes (Jaccard similarity), third-party hosts, MT disclaimer, ICP footer, GTM, HTML hash.

7 · Saturation

Template discovery saturated after ~300 census pages: the last 150 classified pages introduced no new source template. Block discovery saturated inside the deep sample (no new component roots in the last 15 pages). Regional sampling stopped at 28 pairs per region because every pair matched the primary template; the only new signals (MT disclaimer, ICP, China hosts) appeared consistently from the first pairs onward.

8 · Estimation methodology

Bottom-up, in hours with low / most likely / high. Engineering = foundation + templates + variants + blocks + integrations + CWV + accessibility, each estimated once. Content migration = import tooling per template + automated bulk import with remediation + data-driven generation + assets + SEO/redirects. Regional increments are itemized per site (configuration, content migration, translation of UI strings, region-specific development, linguistic QA, regional QA). Coordination = 10% of the subtotal. Duration accounts for dependencies (China hosting, MyIllumina CORS) rather than hours ÷ team size.
